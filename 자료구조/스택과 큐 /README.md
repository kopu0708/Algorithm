## 1. 스택 (Stack)

블록을 쌓듯이 데이터를 저장하는 자료구조. **후입선출(LIFO, Last In First Out)**이 핵심 특징이다. 가장 마지막에 들어온 데이터가 가장 먼저 빠져나간다.

```csharp
Stack<int> stack = new Stack<int>();
stack.Push(1);
stack.Push(2);
stack.Push(3);
Console.WriteLine(stack.Pop());  // 3 (가장 나중에 넣은 게 먼저 나옴)
```

### 1.1 문제: 스택으로 수열 만들기

- **핵심 아이디어**: 스택을 선언하고 오름차순으로 수를 하나씩 세어가며 목표 지점까지 스택에 push한다. 목표 지점에 닿았다면 pop, 이것을 입력받은 배열의 크기만큼 반복하되 만약 최상단(가장 늦게 들어온 숫자)과 목표 숫자가 다르다면 NO를 출력하며 break를 낸다.
- **틀렸던 지점**: 시간 제한 생각 안 하고 string 변수에 `+=`를 써서 답을 썼다. 이렇게 하면 매번 문자열 전체를 복사해서 새로 만들기 때문에 O(N²)에 가깝게 되어 시간초과가 날 수 있다. `StringBuilder.Append`(또는 `AppendLine`)로 바꿔야 O(N)으로 안전하다.
- **시간복잡도**: O(N) — 각 수가 push/pop에 각각 최대 한 번씩만 관여하고, 출력도 `StringBuilder`로 누적하면 문자열 복사 비용 없이 O(N)
- **코드**: [stack1.cs](./stack1.cs)

### 1.2 문제: 오큰수 구하기

- **핵심 아이디어**: 단조 스택이라는 알고리즘이 있다.
  - 스택에 새로 들어오는 수가 top에 존재하는 수보다 크면, 그 수가 top의 오큰수가 된다. 오큰수를 찾았으니 top은 스택에서 pop하고, 새로 들어온 수를 push한다.
  - 오큰수를 구한 후 수열에서 오큰수가 존재하지 않는 숫자는 -1로 출력해야 하기에 미리 -1로 초기화해둔다.
- **틀렸던 지점**: 그냥 접근을 못했다. 브루트포스 방식 말고 어떤 방식이 있는지 생각을 못했다.
- **시간복잡도**: O(N)
- **코드**: [stack2.cs](./stack2.cs)

## 2. 큐 (Queue)

스택과 반대로 **선입선출(FIFO, First In First Out)**. 가장 먼저 들어온 데이터가 먼저 빠져나가고, 뒤에 들어온 데이터는 맨 뒤에 남아 있다.

```csharp
Queue<int> queue = new Queue<int>();
queue.Enqueue(1);
queue.Enqueue(2);
queue.Enqueue(3);
Console.WriteLine(queue.Dequeue());  // 1 (가장 먼저 넣은 게 먼저 나옴)
```

### 2.2 문제: 카드 게임

큐를 잘 이해하고 있는지 묻는 문제라고 한다. 앞에 두 문제 풀어보니 대충 while문 쓰고 해야 하겠구나 감이온다.

- **핵심 아이디어**: 큐는 선입선출이니깐 카드를 다시 넣을 때 그냥 빼고 넣고를 해주면 된다.
- **틀렸던 지점**: 없다. 원트함.
- **시간복잡도**: O(N)
- **코드**: [Queue1.cs](./Queue1.cs)

## 3. 힙 (Priority Queue)

절댓값을 기준으로 정렬되게 하되, 같은 경우 음수가 우선되게 해야 한다. 이 조건을 만족시켜주는 자료형이 `PriorityQueue`이다.

**핵심 성질**: 완전 이진 트리인데, 부모가 항상 자식보다 작다(최소 힙) 또는 크다(최대 힙)는 규칙을 유지하는 자료구조. 정렬된 배열과 달리 완전히 정렬되어 있진 않지만, 대신 삽입/삭제가 O(log N)으로 빠르다. C#의 기본값은 **최소 힙**(우선순위가 작을수록 먼저 나옴)이다.

### 사용법 — `PriorityQueue<TElement, TPriority>`

```csharp
using System.Collections.Generic;

PriorityQueue<int, int> pq = new PriorityQueue<int, int>();

pq.Enqueue(값, 우선순위);   // 값과 우선순위를 따로 넣는다
int x = pq.Dequeue();       // 우선순위가 가장 작은 값을 꺼낸다 (기본: 오름차순)
int top = pq.Peek();        // 꺼내지 않고 우선순위가 가장 작은 값만 확인
int n = pq.Count;           // 현재 저장된 개수 (비어있는지 확인할 때 사용)
```

- **값(TElement)과 우선순위(TPriority)를 분리해서 넣는 이유**: 실제로 꺼낼 값과, 정렬 기준으로 쓸 값이 다를 수 있기 때문이다. 예를 들어 `-5`를 넣으면 꺼낼 때도 `-5`가 나와야 하지만, 정렬 기준은 절댓값인 `5`여야 하는 경우.
- **우선순위가 같을 때(동점) 순서를 추가로 정하고 싶으면, 우선순위 타입을 튜플로 만든다.** C#의 튜플은 첫 번째 원소부터 비교하고, 같으면 다음 원소로 넘어가서 비교한다.

```csharp
PriorityQueue<int, (int, int)> pq = new PriorityQueue<int, (int, int)>();

// 절댓값(1순위 기준) 오름차순, 절댓값이 같으면 원래 값(2순위 기준)이 작은 게 먼저
pq.Enqueue(x, (Math.Abs(x), x));
```

- `Peek()`이나 `Dequeue()`는 큐가 비어있으면 예외가 나므로, 항상 `Count == 0`인지 먼저 확인하고 호출해야 한다.

### 3.1 문제: 절댓값 힙

- **핵심 아이디어**: 절댓값을 기준으로 정렬되게 하되, 같은 경우 음수가 우선되게 해야 한다. 이 조건을 만족하는 자료형이 `PriorityQueue`다. 입력이 0이 아니면 `Enqueue(x, (Math.Abs(x), x))`로 넣기만 하고, 0이면 큐가 비어있으면 0을, 아니면 `Dequeue()`한 값을 출력한다.
- **틀렸던 지점**:
  1. 우선순위를 `int` 하나(절댓값)로만 넣으면, 절댓값이 같은 두 값(`3`과 `-3`) 사이의 순서가 보장되지 않는다. 우선순위를 `(Math.Abs(x), x)` 튜플로 만들어야 절댓값이 같을 때 원래 값 기준으로도 정렬된다.
  2. `Enqueue`는 인자를 정확히 2개(값, 우선순위)만 받는다. 우선순위가 튜플이면 `Enqueue(x, Math.Abs(x), x)`처럼 풀어서 3개를 넘기는 게 아니라, `Enqueue(x, (Math.Abs(x), x))`처럼 튜플 전체를 괄호로 묶어 하나의 인자로 넘겨야 한다.
  3. `queue.Peek()`을 큐가 비어있는지 확인하지 않고 호출하면 예외가 난다 — 스택/덱에서 반복했던 것과 같은 패턴의 실수.
- **시간복잡도**: O(N log N) — `Enqueue`/`Dequeue` 각각 O(log N), N번 반복
- **코드**: [Heap1.cs](./Heap1.cs)

## 4. 코딩테스트 활용 유형

**스택이 자주 쓰이는 문제 유형**

- 괄호 짝 맞추기 (여는 괄호를 넣고, 닫는 괄호 만나면 꺼내서 비교)
- 문자열 되돌리기, 실행 취소(Undo)
- DFS(깊이 우선 탐색) 구현

**큐가 자주 쓰이는 문제 유형**

- BFS(너비 우선 탐색) 구현
- 시뮬레이션 문제 (대기열, 순서대로 처리)
