## 배열

메모리의 **연속 공간**에 값이 채워져 있는 형태. 인덱스로 접근하며, 선언한 자료형만 저장할 수 있다.

- 인덱스는 **0부터 시작**
- 한 번 크기를 정하면 **수정 불가**
- 새 값 삽입이나 특정 인덱스 삭제가 어려움 — 그 주변 값들을 이동시켜야 하기 때문

```csharp
int[] arr = { 1, 2, 3, 4, 5 };

// 인덱스 1(값 2)을 삭제하려면, 뒤의 값들을 앞으로 한 칸씩 밀어야 함
for (int i = 1; i < arr.Length - 1; i++)
{
    arr[i] = arr[i + 1];
}
// arr = { 1, 3, 4, 5, 5 }  ← 마지막 자리는 의미 없는 값이 남음
```

| 연산 | 시간복잡도 | 이유 |
|------|-----------|------|
| 인덱스로 읽기 (`arr[i]`) | O(1) | 주소 계산만 하면 바로 접근 |
| 중간 삽입/삭제 | O(N) | 뒤 요소들을 전부 옮겨야 함 |

## C#의 List\<T\>

배열과 다룰 수 있는 메서드에 차이가 있지만, **내부적으로는 배열을 사용**한다. 다만 크기를 가변적으로 쓸 수 있다는 게 배열과의 차이.

### Add() — 용량에 따라 동작이 다름

```csharp
List<int> list = new List<int>();
Console.WriteLine(list.Capacity);  // 내부 배열의 실제 크기
```

- **용량이 남아있으면** → 그냥 기존 배열에 채우기만 함 (복사 없음, 빠름)
- **용량이 꽉 찼으면** → 더 큰 새 배열을 만들고 기존 값을 전부 복사한 뒤 기존 배열은 버림 (느림)

```
확장 전: [1, 2, 3, 4]                     ← 4칸짜리 배열 (기존 위치)
Add(5) 호출 → 용량 초과!
확장 후: [1, 2, 3, 4, 5, _, _, _]         ← 8칸짜리 배열 (완전히 새로운 위치에 생성)
         (기존 배열은 버려짐, GC 대상)
```

> ⚠️ 리스트가 커질 때 **기존 자리 뒤에 이어붙이는 게 아니다.** 연속된 메모리를 보장해야 하므로, 항상 통째로 새 공간을 확보하고 전체를 복사한다. 이런 확장이 "가끔"만 일어나기 때문에 평균적으로는 여전히 빠른 편이며, 이를 **분할 상환 O(1)** (amortized O(1))이라고 부른다.

### Remove() — 배열을 새로 만들지 않고 값을 당김

```csharp
List<int> list = new List<int> { 1, 2, 3, 4, 5 };
list.Remove(2);
// 2를 지우고, 뒤에 있던 3,4,5를 한 칸씩 앞으로 당김
// 결과: { 1, 3, 4, 5 }
```

새 배열을 만드는 게 아니라, **같은 배열 안에서 해당 인덱스 뒤의 값들을 한 칸씩 당겨오는** 방식이다. 배열에서 삭제할 때와 같은 원리다.

### 파이썬 list와 비교

파이썬 `list`도 구조상 C#의 `List<T>`와 동일하게 **동적 배열**이다 (CPython 내부에서 `PyListObject`가 포인터 배열 `ob_item`을 가짐). 다만 저장하는 것이 다르다.

| | 배열에 저장하는 것 | 인덱스 접근 |
|--|-------------------|------------|
| C# `int[]` | 값 자체 (값 형식) | O(1) |
| 파이썬 `list` | 값이 있는 곳의 주소(참조) | O(1) |
| C# `List<T>` | 값 or 참조 (타입에 따라) | O(1) |

파이썬은 리스트의 각 칸에 값 대신 **그 값을 가리키는 포인터**를 저장한다. "값과 포인터를 묶었다"는 건 이 의미이지, 아래에서 다룰 연결 리스트처럼 노드끼리 연결됐다는 뜻이 아니다. 파이썬 `list`도 여전히 배열 기반이라 인덱스 접근은 O(1)로 빠르다.

## 연결 리스트 (Linked List)

배열, `List<T>`와는 **전혀 다른** 자료구조.

```
Head → [값1|다음주소] → [값2|다음주소] → [값3|다음주소] → null
```

- 각 요소를 **노드(Node)**라고 부른다. 노드는 **값**과 **다음 노드를 가리키는 주소(포인터)**를 가진다.
- 메모리상에 노드들이 **흩어져 있고**, 서로를 포인터로만 연결한다.

```
배열:        [1][2][3][4]   ← 메모리상 붙어있음
연결 리스트:  [1]→...메모리 아무데나...→[2]→...→[3]→...→[4]
```

### 그래서 인덱스 접근이 느림

`Head`부터 시작해서 "다음, 다음, 다음..." 포인터를 따라가야 원하는 위치에 도달한다. 인덱스로 바로 점프하는 게 불가능하다.

```csharp
// C#의 LinkedList<T>
LinkedList<int> list = new LinkedList<int>();
list.AddLast(1);
list.AddLast(2);
list.AddLast(3);

// list[2] 같은 인덱스 접근 자체가 불가능함
// 대신 순회해야 함
var node = list.First;  // Head
while (node != null)
{
    Console.WriteLine(node.Value);
    node = node.Next;
}
```

### 반대로 삽입/삭제는 빠름

배열/List는 중간 삽입·삭제 시 뒤 요소들을 전부 옮겨야 해서 느렸지만(O(N)), 연결 리스트는 **포인터(화살표)만 바꾸면 되므로** O(1)이다. 새 노드를 힙 어딘가에 만들고 앞뒤 노드의 포인터만 연결해주면 끝이라, 기존 노드들을 건드릴 필요가 없다.

## 배열·List vs 연결 리스트 비교

| | 인덱스 접근 | 중간 삽입/삭제 | 메모리 구조 |
|--|-----------|---------------|-----------|
| 배열 / `List<T>` | O(1) 빠름 | O(N) 느림 (이동 필요) | 연속 |
| 연결 리스트 | O(N) 느림 (Head부터 순회) | O(1) 빠름 (포인터만 변경) | 흩어짐 |

**핵심 트레이드오프:** 접근 속도와 삽입/삭제 속도가 정반대다. 값을 자주 읽어야 하면 배열/`List<T>`가 유리하고, 중간 삽입·삭제가 잦으면 연결 리스트가 유리하다.

> 연결 리스트는 이번에 처음 배웠다. 배열/List와 장단점이 정반대라고 큰 그림으로 잡아두면, 나중에 `LinkedList<T>`를 실제로 다룰 때 이해가 수월할 것 같다.
