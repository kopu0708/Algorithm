## 1. 1차원 구간 합

배열의 특정 구간 합(연속된 부분)을 구하는 것. `{2, 3, 4, 5, 6}`이 있으면 "1번째 인덱스부터 3번째 인덱스까지의 합"을 구하는 식이다.

### 1.1 문제 상황

매번 구간이 주어질 때마다 처음부터 다시 더하면:

```csharp
static int RangeSum(int[] arr, int start, int end)
{
    int sum = 0;
    for (int i = start; i <= end; i++)
    {
        sum += arr[i];
    }
    return sum;
}
```

이건 한 번 호출할 때마다 O(N)이다. 이걸 수만 번 반복하면 시간 복잡도가 **O(N × 질문 횟수)**가 되어 시간 초과가 난다.

### 1.2 합 배열(Prefix Sum) 만들기

배열을 하나 더 만들어서 각 인덱스까지의 누적 합을 저장해둔다.

```
{1,2,3,4,5} → 합 배열: {0,1,3,6,10,15}
```

이렇게 구해두면 이후 어떤 구간이든 **뺄셈 한 번**으로 바로 구간 합을 구할 수 있다.

`S[i] = A[0] + A[1] + ... + A[i]`라고 할 때:

```
S[j] - S[i-1] = i에서 j까지의 구간 합
```

합 배열을 구해두면 시간 복잡도가 **O(1)**로 감소한다.

> ⚠️ 합 배열을 만들 때는 원본 배열보다 **한 칸 크게** 만들어야 한다. `S[i-1]`에서 `i=0`일 때 `S[-1]`이 되어 범위를 벗어나는 걸 막기 위해서다. 맨 앞에 `0`을 패딩으로 넣어두면 이 문제를 피할 수 있다.

### 1.3 실전 코드

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        int[] arr = { 1, 2, 3, 4, 5 };
        int[] prefix = new int[arr.Length + 1];

        for (int i = 0; i < arr.Length; i++)
        {
            prefix[i + 1] = prefix[i] + arr[i];
        }
        // prefix = [0, 1, 3, 6, 10, 15]

        // 1번째부터 3번째 인덱스까지의 합 (2+3+4=9)
        Console.WriteLine(RangeSum(prefix, 1, 3));  // 9
    }

    // S[j+1] - S[i] = arr[i]부터 arr[j]까지의 구간 합
    static int RangeSum(int[] prefix, int i, int j)
    {
        return prefix[j + 1] - prefix[i];
    }
}
```

**실전 문제 형태 (배열 크기·질의 개수 입력, 여러 쿼리 처리)**

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        string input = Console.ReadLine();
        int[] a = Array.ConvertAll(input.Split(' '), int.Parse);  // 배열 크기, 질의 개수

        string arrInput = Console.ReadLine();
        int[] arr = Array.ConvertAll(arrInput.Split(' '), int.Parse);

        int[] prefix = new int[arr.Length + 1];
        for (int i = 1; i < prefix.Length; i++)
        {
            prefix[i] = prefix[i - 1] + arr[i - 1];
        }

        for (int i = 0; i < a[1]; i++)
        {
            string queryInput = Console.ReadLine();
            int[] query = Array.ConvertAll(queryInput.Split(' '), int.Parse);
            int answer = prefix[query[1]] - prefix[query[0] - 1];  // 1-based 인덱스 보정
            Console.WriteLine(answer);
        }
    }
}
```

## 2. 2차원 구간 합

### 2.1 왜 한 줄씩 계산하면 안 되는가

2차원 배열의 특정 사각형 영역 합을 구하는 문제를 처음 보면, "행마다 1차원 구간 합을 만들어서 필요한 행들을 더하면 되지 않을까" 하는 생각이 먼저 든다. 하지만 이렇게 하면:

```csharp
// 각 행마다 1차원 prefix를 만들어도
int sum = 0;
for (int row = r1; row <= r2; row++)
{
    sum += rowPrefix[row, c2] - rowPrefix[row, c1 - 1];  // 필요한 행만큼 다시 반복
}
```

**질문 1번당 O(N)**(행 개수만큼)이 되어버려서, 애초에 얻으려던 "O(1)에 답 구하기"를 못 얻는다. 코드도 길어지고 시간복잡도도 커지는 걸 확인하고 나서 방향을 바꿔야 했다.

### 2.2 2차원 합 배열 공식

```
D[i][j] = D[i][j-1] + D[i-1][j] - D[i-1][j-1] + A[i][j]
```

두 축(행, 열)으로 각각 더하고, 겹치는 부분을 한 번 빼준 다음, 지금 칸의 값을 더하는 식이다.

**직접 검증 (matrix = {1,2},{3,4}):**

```
prefix[1,1] = 0 + 0 - 0 + 1  = 1   ✓ (왼쪽 위 1칸)
prefix[1,2] = 1 + 0 - 0 + 2  = 3   ✓ (1행 1~2열: 1+2)
prefix[2,1] = 0 + 1 - 0 + 3  = 4   ✓ (1~2행 1열: 1+3)
prefix[2,2] = 3 + 4 - 1 + 4  = 10  ✓ (전체 합: 1+2+3+4)
```

**구간(사각형 영역) 합 구하기:**

```
S[r2][c2] - S[r1-1][c2] - S[r2][c1-1] + S[r1-1][c1-1]
```

1차원의 `S[j] - S[i-1]`과 같은 원리인데, 사각형이라 뺄셈이 두 번 필요하고 겹치는 부분을 다시 더하기로 보정해야 한다 (포함-배제 원리).

### 2.3 실전 코드

```csharp
using System;

class Program
{
    static void Main(string[] args)
    {
        string input = Console.ReadLine();
        int[] a = Array.ConvertAll(input.Split(' '), int.Parse);  // 배열 크기, 질의 개수

        int[,] matrix = new int[a[0], a[0]];

        for (int i = 0; i < a[0]; i++)
        {
            string[] row = Console.ReadLine().Split(' ');
            for (int j = 0; j < a[0]; j++)
            {
                matrix[i, j] = int.Parse(row[j]);
            }
        }

        int[,] prefix = new int[a[0] + 1, a[0] + 1];

        for (int i = 1; i < a[0] + 1; i++)
        {
            for (int j = 1; j < a[0] + 1; j++)
            {
                prefix[i, j] = prefix[i, j - 1] + prefix[i - 1, j] - prefix[i - 1, j - 1] + matrix[i - 1, j - 1];
            }
        }

        for (int i = 0; i < a[1]; i++)
        {
            string queryInput = Console.ReadLine();
            int[] xy = Array.ConvertAll(queryInput.Split(' '), int.Parse);
            // xy[0]=r1, xy[1]=c1, xy[2]=r2, xy[3]=c2

            int result = prefix[xy[2], xy[3]]
                       - prefix[xy[0] - 1, xy[3]]
                       - prefix[xy[2], xy[1] - 1]
                       + prefix[xy[0] - 1, xy[1] - 1];

            Console.WriteLine(result);
        }
    }
}
```

### 2.4 시간복잡도

```
합 배열 만들기: O(N²) — 한 번만
쿼리 M개 처리:  O(1) × M = O(M)
전체:          O(N² + M)
```

행렬 크기가 커도, 쿼리가 몇만 번이어도 충분히 빠르다.

> 2차원 배열 합 문제를 처음 보고 한참 머리를 쥐어짰다. 처음엔 한 줄씩만 받아 계산하는 방법을 생각했는데, 코드가 길어지고 시간복잡도가 커지는 걸 보고 생각을 바꿨다. "두 축으로 더하고 겹치는 부분을 빼준 다음 포함되지 않은 부분을 더한다"는 아이디어까지 도달하니, 그 다음은 금방 식을 유도할 수 있었다.
>
> ```
> D[X2][Y2] - D[X1-1][Y2] - D[X2][Y1-1] + D[X1-1][Y1-1]
> ```

## 3. 오답 노트 — 나머지 합 구하기 (2026-07-30)

나머지 합 구하기 문제를 처음 보고, 배열을 나누고 나누면 끝인 줄 알았는데 **모든 구간의 쌍**을 구해야 한다는 것을 알았다.

**핵심 아이디어**: 합 배열에서 **나머지 값이 같은 인덱스끼리의 개수**를 세서, 그중 2개를 뽑는 경우의 수를 구하면 된다.

- 순서 상관없이 조합의 개수를 세는 방법을 어떻게 코드로 옮겨야 하나 한참 헤맸다.
- 공식: `nC2 = n(n-1)/2`

> 💡 **투 포인터 문제와의 차이점**: 이 문제는 "구간 합이 K의 배수인 쌍의 개수"를 세는 문제였다. 반면 아래 4장의 투 포인터 문제는 "구간 합이 정확히 N인 경우의 수"를 세는 문제다. 같은 나머지 연산이라도 **"배수 쌍 세기"**와 **"정확한 값 찾기"**는 전혀 다른 도구(조합 공식 vs 투 포인터)가 필요하다. 이번에 투 포인터 문제에서 나머지 접근법이 틀렸던 이유가 바로 이 둘을 혼동했기 때문이었다.

## 4. 투 포인터

2개의 포인터로 알고리즘의 시간 복잡도를 최적화하는 기법. 정렬된(또는 순서가 있는) 배열에서 구간을 유지하면서, 매번 처음부터 다시 계산하지 않고 **한 칸씩만 더하거나 빼서** 구간 합을 O(1)에 갱신하는 것이 핵심이다.

### 4.1 문제: 연속된 자연수의 합으로 나타내는 가짓수

자연수 N을 입력받아, N을 **연속된 자연수의 합**으로 나타낼 수 있는 가짓수를 구하는 문제.

예: N=15 → `15`, `7+8`, `4+5+6`, `1+2+3+4+5` → 총 4가지

### 4.2 시행착오 기록

#### 시도 1 — 2차원 합 배열 발상에서 온 나머지 접근 (❌)

앞서 배운 2차원 합 배열을 이용하면 될 듯해서, 입력받은 수까지 순서대로 나열한 배열을 만들고 합 배열을 만든 후, 입력받은 수로 나누었을 때 나머지가 0인 개수를 구하면 될 거라 생각했다.

```csharp
int[] prefix = new int[Q + 1];
for(int i = 1; i < prefix.Length; i++)
    prefix[i] = prefix[i - 1] + arr[i - 1];

int answer = 0;
foreach(int a in prefix)
    if(a % Q == 0) answer++;

Console.WriteLine(answer - 1); // 0은 제외
```

예시 답은 나왔지만 틀렸다는 판정을 받았다. 이유는 `prefix[j] % N == 0`은 `prefix[j]`가 N의 배수라는 뜻이지, "어떤 연속 구간의 합이 N"이라는 뜻이 아니기 때문이다. 예를 들어 N=15일 때 `prefix[j] = 30`이어도 나머지는 0이지만, 30은 15가 아니다. 즉 이 로직은 "구간 합이 N인 경우"가 아니라 "prefix 값 자체가 N의 배수인 인덱스가 몇 개인가"를 세고 있던 것.

직접 손으로 검증해보니 5, 15 같은 수는 우연히 정답이 나왔지만 **N=8**에서는 답이 틀렸다.

#### 시도 2 — 투 포인터 도입, 그러나 매번 처음부터 합 계산 (❌ 시간초과)

합 배열을 만들 필요는 없고, 순서대로 나열한 배열에서 시작점(`start_index`)과 끝점(`end_index`) 두 개의 인덱스 변수만 있으면 된다는 걸 깨달았다.

```csharp
while(end_index != Q)
{
    for(int i = start_index; i < end_index + 1; i++)
        sum += arr[i];

    if(sum == Q) { answer++; end_index++; }
    else if (sum < Q) end_index++;
    else if (sum > Q) start_index++;

    sum = 0;
}
```

정답은 나왔지만, `while` 안에서 매번 `for`문으로 처음부터 합을 다시 계산하므로 **O(N²)**. 시간제한 2초 안에는 못 들어간다.

#### 시도 3 — 진짜 투 포인터: 한 칸씩만 더하고 빼기 (✅ O(N))

핵심 깨달음: 인덱스를 하나 이동할 때마다 기존 `sum`에 더하고 빼기만 해주면 된다.

- `sum`을 **1**로 초기화 (자기 자신 `Q` 하나짜리 케이스를 미리 포함)
- `sum < Q` → 끝 인덱스를 늘리고 그 값을 더한다
- `sum > Q` → 시작 인덱스 위치의 값을 **먼저 빼고** 그다음 인덱스를 늘린다 *(이 순서가 중요하다 — `sum`이 항상 "현재 구간의 합"이라는 불변 조건을 유지해야 하므로)*

```csharp
int answer = 1;              // Q 자기 자신 케이스 미리 카운트
int start_index = 0, end_index = 0;
int sum = 1;

while(end_index != Q - 1)
{
    if(sum == Q)
    {
        answer++; end_index++;
        sum += arr[end_index];
    }
    else if (sum < Q)
    {
        end_index++;
        sum += arr[end_index];
    }
    else if (sum > Q)
    {
        sum -= arr[start_index];
        start_index++;
    }
}

Console.WriteLine(answer);
```

**범위 오류 발견**: `end_index`가 `Q-1`(마지막 인덱스)에 도달했을 때, `sum == Q`가 되면 `end_index++` 후 `arr[end_index]`(= `arr[Q]`)에 접근하려다 `IndexOutOfRangeException` 발생. 해결 방법은 두 가지:

1. 예외처리로 방어
2. **`end_index`가 `Q-1`까지만 돌도록** 루프 조건을 제한하고, `Q` 자기 자신 케이스를 `answer = 1`로 미리 세어둔다 (채택한 방법)

**왜 `Q-1`에서 멈춰도 안전한가?**
`arr[Q-1]`의 값 자체가 `Q`이므로(배열이 `1, 2, ..., Q` 순서), `end_index == Q-1`로 끝나는 구간은:
- 원소가 1개면 합이 정확히 `Q`
- 원소가 2개 이상이면 이미 `Q`를 포함한 채로 양수를 더 더하니 합이 무조건 `Q`보다 커짐

→ 즉 "마지막 인덱스에서 끝나는 멀티 항목 구간"은 애초에 `sum == Q`가 될 수 없어서, 놓치는 케이스 없이 안전하게 루프를 끝낼 수 있다.

### 4.3 배운 점 정리

- **나머지(mod) 접근과 투 포인터는 다른 문제에 쓰인다.** "구간 합이 K의 배수인 쌍의 개수"는 나머지+조합으로, "구간 합이 정확히 N인 경우의 수"는 투 포인터로 푼다. 겉보기엔 비슷해 보여도 완전히 다른 질문이다.
- **투 포인터의 핵심은 "매번 다시 계산하지 않는 것"이다.** `sum`을 매번 처음부터 구하면 투 포인터를 썼다고 해도 여전히 O(N²)이다. 한 칸 이동할 때 그 값만 더하거나 빼야 진짜 O(N)이 된다.
- **포인터 이동과 sum 갱신의 순서가 중요하다.** `sum`이 항상 "현재 구간의 합"이라는 불변 조건(invariant)을 유지하도록, 값을 빼는 것과 인덱스를 늘리는 것의 순서를 정확히 지켜야 한다.
- **경계값(맨 처음/맨 끝)은 항상 별도로 검증한다.** 배열 범위를 벗어나는 실수는 대개 루프의 시작/끝 지점에서 발생한다. 문제의 구조(예: `arr[Q-1] = Q`)를 이용하면 예외처리 없이도 우아하게 경계를 처리할 수 있는 경우가 있다.

### 4.4 같은 유형 문제 
[투 포인터] 두 수의 합이 M인 쌍의 개수

- **핵심 아이디어**: 배열을 정렬한 뒤, 양 끝에서 포인터를 좁혀가며 합을 비교한다.
  합이 M보다 크면 큰 값(end)을 줄이고, 작으면 작은 값(start)을 늘린다.
- **틀렸던 지점**: 처음엔 조건 방향이 반대였다 — 합이 클 때 `start++`, 작을 때 `end--`를 해서
  오히려 합이 더 벌어지는 쪽으로 움직였다. "합을 줄이려면 큰 값을, 늘리려면 작은 값을 움직인다"
  는 방향성을 헷갈리지 말 것.
- **시간복잡도**: O(N log N) — 정렬 O(N log N) + 투 포인터 순회 O(N)
- **코드**: [two_sum_pointer.cs](./two_sum_pointer.cs)

[투 포인터] '좋은 수' 구하기  N개의 수에서 다른 두 수의 합으로 표현되는 수 개수 

- **핵심 아이디어**: 양 끝 점에서 시작하며 합이 같은 수를 찾으면 즉시 탈출한다.  
- **틀렸던 지점**: 처음 문제를 보고 양 끝에서 시작하지 않고 두 포인터를 같은 지점에 놓고 시작했다. 두 포인터가 같은 지점을 가르키면 안된다. 
- **시간복잡도**: O(N log N) -  O(N log N) 정렬 + O(N²) 탐색 (N ≤ 2,000이라 시간 제한 내 통과)
- **코드**: [find_good_num.cs](./find_good_num.cs)

## 5. 슬라이딩 윈도우 
또 새로운 알고리즘이다. 투 포인터와 비슷한데 이건 범위를 지정한 다음 범위를 유지한 채로 이동하며 문제를 해결한다고 한다. 

이번에도 교재 보기 전에 풀어봐야겠다. 

### [슬라이딩 윈도우] DNA 비밀번호 — 조건을 만족하는 길이 P 부분 문자열의 개수
 
- **핵심 아이디어**: 크기 `P`로 고정된 윈도우를 오른쪽으로 한 칸씩 밀면서, 매번 새로 세지 않고 빠지는 문자 하나·들어오는 문자 하나만 카운터에서 갱신한다(O(1) 갱신).
- **틀렸던 지점**: 이동 종료 조건을 윈도우 크기(`P`)와 비교하는 값으로 잘못 잡아서, 우연히 포인터 값이 그 값을 스칠 때 이동이 멈추고 같은 위치를 반복해서 빼는 바람에 카운트가 무너지고 무한 루프에 빠졌다. 올바른 종료 조건은 "다음 칸이 문자열 범위 안에 있는가"(`Tail`이 마지막 인덱스인지)여야 했다. 또한 포인터를 먼저 옮기고 갱신하려다 인덱스 초과 위험이 있어, **먼저 갱신 → 그다음 이동** 순서로 바꿔야 안전했다.
- **시간복잡도**: O(N) — 초기 윈도우 세팅 O(P) + 슬라이딩 O(N), 매 이동이 O(1)
- **코드**: [DNAPassword.cs](./DNAPassword.cs)
