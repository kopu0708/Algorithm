## 시간 복잡도 표기법 알아보기 
알고리즘에서 시간 복잡도는 주어진 문제를 해결하기 위한 연산 횟수를 이야기한다. 

3가지 유형이 있다고 함 
- 빅-오메가 : 최선일 때(best case)의 연산 횟수를 나타낸 표기법 
- 빅-세타   : 보통일 때(average case)의 연산 횟수를 나타낸 표기법 
- 빅-오     : 최악일 때(worst case)의 연산 횟수  

1~100까지의 사이의 무작윗값을 찾아 출력하는 코드는 빅-오메가일 경우 1번, 빅-세타는 N/2, 빅-오는 N번이라고 한다.
```C#
using System;
class Program
{
    static void Main()
    {
        Random random = new Random();
        int target = random.Next(1, 101);  // 찾을 목표값 (미리 정해져 있다고 가정)

        int[] arr = new int[100];
        for (int i = 0; i < 100; i++)
            arr[i] = i + 1;  // 1~100이 순서대로 들어있는 배열

        int count = 0;  // 연산 횟수 세기
        for (int i = 0; i < arr.Length; i++)
        {
            count++;
            if (arr[i] == target)
            {
                Console.WriteLine($"{target}을 {count}번 만에 찾음");
                break;
            }
        }
    }
}
```

코딩 테스트에서는 빅-오 표기법을 기준으로 수행 시간을 계산하는 것이 좋다. 

코딩 테스트에서는 여러개의 테스트 케이스를 통과해야 합격으로 판단되기에 최악의 경우를 염두에 두어야 한다. 

빅-오 표기법으로 시간 복잡도를 표현한 그래프를 보면 데이터(N)의 증각에 따라 수행 시간이 달라짐을 확인 할 수 있다. (인터넷 검색해서 찾으면 금방 나옴) 

대표적인 빅-오 표기법들 
| 표기법 | 이름 | 예시 |
|--------|------|------|
| O(1) | 상수 시간 | 배열 인덱스 접근 |
| O(log N) | 로그 시간 | 이진 탐색 |
| O(N) | 선형 시간 | 선형 탐색 |
| O(N log N) | 선형로그 시간 | 병합 정렬, 퀵 정렬 |
| O(N²) | 이차 시간 | 버블 정렬 |

그럼 이걸 어떻게 활용해야 할까? 

나중에 정렬 알고리즘 할 때 자세히 할건데 상수는 시간 복잡도에서 제외되고, 시간 복잡도는 가장 많이 중첩된 반복문을 기준으로 도출한다. 

이를 바탕으로 문제를 어떤 방식으로 풀어야할지 생각하거나 시간 복잡도를 분석해 문제에서 사용할 수 있는 알고리즘을 선택할 수 있다.

코딩테스트에서 흔한 판단 기준:
- N ≤ 1,000       → O(N²)도 괜찮음
- N ≤ 100,000     → O(N log N) 필요
- N ≤ 10,000,000  → O(N) 이어야 함

## 디버깅의 중요성
프로그램에서 일어난 문법 오류나 논리 오류를 찾아서 고치는 과정을 디버깅이라 한다. 

문법 오류는 뭐 실행도 하기 전에 오류가 나서 잡아주니 괜찮은데 논리 오류는 내 의도랑 다르게 돌아가고 다양한 형태로 발생해서 골치아프다. (물론 AI한테 맡기면 웬만하면 해결됨)

근데 코딩 테스트 환경에서는 AI를 못쓰니깐 공부하는 거 아니겠는가 

크게 3가지 방법이 있는데 

1.Console.WriteLine()으로 중간값 찍어보기 - 가장 기본적이고 확실한 방법이다.
2.중단점을 설정하고 한줄 식 실행하거나 다음 중단점까지 실행하기 - 이 과정에서 추적할 변숫값도 지정 할 수 있다. 변숫값이 자신의 의도대로 변하는지 파악한다.
3.작은 입력값으로 먼저 테스트 - N = 100 문제라도 N = 3으로 줄여서 손으로 계산한 답과 비교 할 수도 있다.
