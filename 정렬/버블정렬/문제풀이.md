# 버블 정렬

한 일주일 딴 짓 하느라 업데이트가 안됐다. 논건 아니고 친구랑 둘이서 확장 프로그램 만들어보자고 이야기 나와서 그거 하느라 잠시 공부를 미뤄놨다.

아무튼 시작하자 

버블 정렬의 핵심 이론은 두 인접한 데이터의 크기를 비교하여 정렬하는 방법이다. 간단하게 구현이 가능하지만 시간복잡도는 O(n^2)으로 느린편이다.

루프 돌면서 데이터 간의 swap연산을 통해 정렬한다.

```C#
  int[] arr = new int[] { 2, 3, 1, 5, 4 };
  int temp = 0;
  for(int i = 0; i < arr.Length; i++)
  {
      for(int j = 0; j < arr.Length -1; j++)
      {
          if (arr[j] > arr[j + 1])
          {
              temp = arr[j];
              arr[j] = arr[j + 1];
              arr[j + 1] = temp;
          } 
      }
}
```
구조는 위와 같다. 

그렇게 복잡한 로직이 아니라서 금방 이해할 수 있다. 바로 문제를 하나 풀어보겠다. 위 코드를 복사해서 써도 될 정도로 간단한 문제다.

## 버블 정렬 프로그램 1 
```c++
bool change = false;
for(int i = 1; i <= n + 1; i++)
{
  change = false;
  for(int j = 1; j <= n - 1; j++){
    if(a[j] > a[j + 1]) {
      change = true;
      swap(a[j], a[j + 1]);
    }
  }
  if(change == false){
    cout << i << '\n';
    break;
  }
}
```
위 코드에서 n은 배열 크기, a는 수가 들어 있는 배열이다. 수는 배열의 1번 부터 채운다고 한다. 

위 코드를 실행 시켰을 때 어떤 값이 출력되는지 구하는 프로그램을 작성하는 문제이다. 

일단 c++로 프로그램이 작성되어 있는데 코드를 읽어보면 swap이 일어나지 않았을 때를 구하는 문제이다. 

swap이 일어나지 않았다는 것은 뒤에 있는 숫자들은 정렬되어 있다는 것이므로 즉 마지막으로 정렬되는 지점을 구하는 문제이다. 

그럼 위 코드를 그대로 c#으로 옮기면 풀리는 거 아닌가?

```c#
using System;

class Program
{
    static void Main()
    {
        int n = int.Parse(Console.ReadLine());
        int[] arr = new int[n];
        for(int i = 0; i < n; i++)
        {
            arr[i] = int.Parse(Console.ReadLine());
        }
        bool swap = false;
        int temp = 0;
        for (int i = 0; i < n; i++)
        {
            swap = false;
            for(int j = 0; j < n - 1; j++)
            {
                if (arr[j] > arr[j + 1])
                {
                    temp = arr[j];
                    arr[j] = arr[j + 1];
                    arr[j + 1] = temp;

                    swap = true;
                }
            }

            if(swap == false)
            {
                Console.WriteLine(i);
                break;
            }
        }
    }
}
```
그래서 이렇게 코드를 작성했는데 시간초과가 난다고 한다. 음.... 뭐지? 보아하니 for문을 다 돌면 안되나 보다. 

좀 고민해보다가 마땅한 방법이 떠오르지 않아 책을 봤는데, 버블 정렬은 최대 이동거리가 결국 1이다. 바로 다음 인덱스와 비교해서 교환하기 때문이다.

즉 데이터의 정렬 전 index와 정렬 후 index를 비교하여 왼쪽으로 가장 많이 이동한 값을 찾으면 이 문제를 해결할 수 있다고 한다.

원리를 알아보면 오름차순으로 정렬한다고 했을 때, 오른쪽으로 이동하는 것은 한 루프에서 여러번 연속적으로 일어날 수 있다.

반면에 왼쪽 이동은 한 루프에 단 한번이다. 왜냐하면 스캔은 계속 왼쪽으로 이동하기 때문이다. 

각 원소가 왼쪽으로 이동해야하는 남은 거리는 각 루프당 정확히 1씩 줄어든다. 서로 다른 원소들은 왼쪽으로 이동으로 동시에, 독립적으로 진행되기 때문에 한 원소가 다른 원소를 기다리게 하지 않는다.

따라서 가장 멀리 이동해야 하는 원소가 제자리에 도착하는 순간에는 나머지도 모두 도착해 있다는 의미이다. 

이를 요약해서 가장 중요한 내용만 한 줄로 남기자면 버블 정렬의 원소 이동은 오른쪽 방향은 빠르고 왼쪽은 느리다는 것이다.
